# Windows details and genre fixes

Build: 2.7.0+30000191

- Windows YouTube trailer actions enter the embedded player even when an
  older external-browser preference is saved, in library and discovery views.
- Discovery-only TMDB IDs skip Jellyfin ThemeMedia requests to avoid HTTP 400.
- Embedded player lifecycle and YouTube error codes are included in diagnostics.

- Detail requests now explicitly include provider IDs, studios, taglines,
  original titles, remote trailers and local trailer counts.
- Episode requests include the authenticated user. Episode/season lists ask
  for additional metadata required by their detail layouts.
- Trailer/extras loading starts ahead of optional ratings/recommendations.
- Local trailer lookup has a five-second deadline. Failed YouTube extraction
  can open the trailer in the Windows browser; kids mode prevents this fallback.
- Unresolved YouTube webpages are never passed to mpv on Windows. Trailer
  startup has a 25-second watchdog, audio setup a three-second deadline and
  browser launch a five-second deadline. A stalled attempt leaves loading state.
- Genre requests no longer include image-tag properties as ItemFields.
  Zero-count genre DTOs are verified using item queries rather than hidden
  immediately. Initial artwork concurrency is reduced from twelve to four.

- Read-only server checks measured filtered Genres at 35-38 seconds, with
  valid HTTP 200 responses. Genre requests now allow 60 seconds to receive
  data and reuse successful results for two minutes, scoped to user and query.
  Identical concurrent requests share one fetch; failures remain retryable.
  The first uncached load can still take approximately 40 seconds.

- Visible image providers promote queued requests, and cast portraits use
  high priority with decode sizes bounded to their displayed dimensions.
- Optional prefetch queues are capped at 16 in SpeshTV native builds. Older
  queued prefetch is discarded; visible requests and cached files are retained.
- Collection membership scans run two requests at a time rather than twelve,
  and stop issuing new requests after the detail view is disposed.

- Windows YouTube trailers use embedded Edge WebView2 with the official
  iframe player API instead of extracted media URLs. The player page is
  served only on loopback with a real referrer and contains no server tokens.
  Leaving the screen unloads the WebView and closes the local page server.
  Embed failures retain the existing external-browser fallback.
